# Qwen3-VL-8B paired real-gold quality protocol

Frozen before these 8B quality outputs exist. Purpose: empirically compare AR and JetSpec answer scores, not to prove theorem-level losslessness or infer score equivalence from a confidence interval containing zero.

Use the previously fixed TextVQA/DocVQA/ChartQA 256-question subsets, same pinned data/real gold/ids/image hashes and reference metric code as `native_quality_v1`; record all 768 prompts and human labels. Four initial warmup calls per task are excluded from scores. Each target system has one fresh vLLM process, batch1, the A6000 GPU selected before the first successful JetSpec smoke; AR and JetSpec use the same physical card, same Qwen3-VL-8B BF16 and same image/prompt templates/temperature0/seed43/128-token output cap. AR uses native defaults; SD uses the pinned method-specific spatial adapter and stock target rejection logic, target and draft FlashAttention, S7/B8. Preserve runtime config, actual target/draft backend classes and target head checks; no profiling hooks, do not use quality timing as speed evidence. All method CPU checkpoint/export tensor checks must pass and source/target/data digests must match.

Each physical request has a fresh UUID. Record full prompt token IDs, original image SHA, question ID, gold answers, complete output tokens/text and termination. Score the *complete decoded text* identically for all two arms as the primary quality metric, matching the previous native-quality actual execution. Also record the old first-nonempty-line `extract_short_answer` preprocessing with exactly the frozen function, as a separately labeled secondary sensitivity analysis. Both are prespecified here; neither may be selected after seeing scores. Dataset manifests describe the first-line rule, so the full-text primary deviates from that old description and must be disclosed.

Each complete arm requires 3×256 scored rows + 3×4 warmups, no failed requests. Pair by task and ID and reject input-token/image/gold/group mismatch. Recompute scores from recorded text and independent fixed real-gold metadata, never use AR answers as gold. Report AR and each SD's score for each task, delta in percentage points and seed42/2000 percentile bootstrap resampling whole image/page groups; report exact token/text equality, changed-score questions and finish/length totals. Keep all raw data, source/plan/adapters and resource sample hashes. One execution per arm cannot estimate seed/card/run variance; 256 per task is not full benchmark, training/evaluation overlap for these 8B drafters is not yet audited, and CI containing zero does not prove equivalence or noninferiority. Score agreement alone does not establish the speculative verification algorithm or correctness of the implementation.

The code-level theoretical argument is the public vLLM greedy target-verification/rejection path under its mathematical assumptions; inference uses BF16 and different verification shapes, so practical token outputs may diverge. The native runner and worker preserve the public target verifier and reject synthetic numerical-profile overrides. Runtime replay of selected sampler decisions is separately queued; it is not retroactive proof of unobserved original decisions.
