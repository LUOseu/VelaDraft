## 1. 目标与证据

在已合并的 fixed LRU（`train.online_feature_cache_gb`，默认 0=off）之上，新增**可选**的 adaptive
payload 预算：内存充足时等价于 fixed cap；压力下降时立即收缩（LRU 逐出、之后 miss 按参考路径重算），
压力恢复后阶梯回涨；传感器不可用或未启用时行为与 BASE 完全一致。动机：共享节点上让缓存把 host RAM
让给 trainer/其他子系统，避免缓存成为 OOM 的最后一根稻草（W1 已证“收缩是安全阀，不是提速杠杆”）。

证据（CPU 可复现；GPU 实测仅作计数器校验）：

- W1：仿真逐计数器复现 S3/S2 两条历史 run；5 条 GPU ground-truth 腿（off/10/25/50%/8 MiB）与预测
  **逐值一致**（C0 已抽查 5/5，REGISTRY 复核记录 23:24–23:39）；不足容量扫描见 REPORT §W1；
  记录 `d4-gpu-*`、`d4-sim-*`（EXPERIMENTS.jsonl）。
- W2：确定性压力轨迹（真实 129 行访问顺序 `order_sha1 4e037b36…`；脚本化 cgroup-v2 轨迹
  square/pulse）驱动**真实 controller**：修复后零 reserve 越界、零 physical overrun，命中数
  ≈ hindsight 静态上界（260 vs 262 / 保守静态 7）；harness 证伪并修复了“cap 低于 4 GiB 高水位时
  收缩后无法回涨”的缺陷（回归测试 `test_small_cap_below_the_watermark_regrows_after_a_shrink`）。
  证据：REPORT §W2；`research/rsi/d4/evidence/w2_cpu/`（含 pre-fix 与 post-fix 轨迹 JSONL）；
  controller 文件 sha1 `3d48e108…`；记录 `d4-w2-*`。
- 测试：本 worktree 全套件 **489 passed / 6 skipped / 0 failed**（2026-10-14 23:5x）；其中
  `tests/test_cache_budget.py` 13 条 + `tests/test_online_mode.py` §5b 4 条。
- 对照口径：上述全部为**确定性策略**（固定压力/预算轨迹）A/B；租约内的运行时压力对照将只报
  wall/内存/命中率，不宣称 parity 或等价（遵 REGISTRY §7 第 1 条）。

## 2. 最小改动面（opt-in，默认行为不变；已实现，未提交）

**新文件** `vlm_dflash/target/cache_budget.py`（248 行，stdlib-only，无新依赖）：
- `MemorySample` / `read_memory_sample()`：cgroup v2 `memory.max|current` → v1 → `/proc/meminfo`
  MemAvailable → `("unavailable", None, None, None)`。
- `BudgetParams`：reserve = max(1 GiB, 10%)；low watermark 768 MiB；high watermark 4 GiB
  （**增长门限取 `min(high_watermark, bound)`**，保证 cap 低于高水位也能回涨）；shrink tolerance
  256 MiB；grow 12.5%/步、最小 32 MiB；min interval 0.5 s。
- `CacheBudgetController(cap_bytes, *, job_share_bytes=None, params=BudgetParams(), sensor=None, clock=None)`
  → `observe() -> int`（按 min interval 节流）、`budget_bytes`、`stats()`。

**`vlm_dflash/target/online.py`（+72/−9）**：
- `_init`（~L423–440）：`(cfg.get("train") or {}).get("online_feature_cache_adaptive", False)`；
  非 bool → `ValueError`；仅当 `adaptive and cache_capacity_bytes > 0` 时构建 controller。
  **默认 False → controller=None，路径与 BASE 逐字节一致。**
- `cache_budget_bytes()`（~L637–646）：有 controller → `observe()`；否则 = 配置 cap。
- `_trim_record_cache(budget)`（~L648）：payload>budget 时 LRU 逐出；lookup/store 都先刷预算：
  lookup 前按预算裁剪（压力即时生效）；store 时记录 > 预算 → `skipped_too_large`（与 BASE 的
  oversized 语义一致）。budget=0 受支持（不存，账目保留）。
- `summary()`（~L718–733）：adaptive 开启时 `feature_source.feature_cache` 增加 `budget_bytes`
  与 `adaptive_budget`（cap/job_share/budget/allowed/reserve/adjustments/shrinks/grows/传感器
  快照/note）；关闭时输出与 BASE 相同。
- **无 config.py / cli.py / train.py / resume 改动**：键与 `online_feature_cache_gb` 同例从 cfg dict
  读取（PR #6 未动 config.py）。若 C0 希望登记进公共 config 文档/schema，请 C0 定稿；本提案不预置。

语义保证（REGISTRY §7 第 1 条逐项）：
- bool、默认 false、仅与 `gb>0` 联动；**`gb` 为硬 cap**（`budget ≤ min(cap, share)`，代码断言
  budget 不超 cap）。
- **绝不改变消费行/顺序/次数**：只决定“已抽取记录是否保留”；访问序列仍由 loader/digest 决定，
  miss 一律按参考路径重算（既有 bf16 grouping 漂移 caveat 不变）。
- **不进 `training_plan_digest`**（与 `gb` 同例）；开启时写 run metadata
  （`train_summary.json` → `feature_source.feature_cache`）；lane EXPERIMENTS `cache_mode`
  记录 kind/caps/job share/sensor kind。
- 无传感器 → 保持当前值（启动时 = cap，即 fixed 策略）；运行时无全局 GC/重采样。
