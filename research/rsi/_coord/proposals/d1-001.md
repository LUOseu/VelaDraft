## 1. 目标与证据

在**冻结逻辑 optimizer batch、anchor 表、noise/label/mask 与原始权重**的前提下，
只改变批内物理 microbatch 组合（按 (C,A) 或拟合成本排序分组），并保留
`g_i = 1/(R·Z_ref_mb(i))` 的逐样本权重（R=参考物理批数），使累计目标与 shipped
1×N 路径严格等价（fp64 oracle PASS；bf16 实测 loss 差 ≤1e-4、grad 差 ≤5.2e-3、
update 差 ≤6.6e-8）。收益（冻结 store 实测，同 anchor 表，8 batch 配对）：

- 真实多轮混合（W3, k=4）：整步 **cost +19.0% / grid +18.8%**（≥15% 门槛 ✓）；
  W3 k2 +10.7%；W2 k2 +9.1%；
- 构造混合池（W1+W2 1:1）：k2 **+23~24%**，k4 **grid +24.7% / cost +24.0%**；
  split-only（只拆不排）k2 +7%、k4 +18%；
- 峰值显存 −20~58%（17.6→11.9 / 23.4→14.8 / 25.0→10.6 GiB，见表）；
- k=4 的去相关池上 2D-aware（cost/grid）比一维排序再快 3~4pp；k=2 无显著差。
- 单池 A≈const（W0/W1）：整步中性（边界证据）。

## 2. 最小改动面（全部 opt-in；默认行为不变）

1. `vlm_dflash/dflash/trainer_core.py::DFlashTrainerModule.forward`（L674）
   新增两个可选参数（默认 None ⇒ 走原路径）：
   - `anchor_table: tuple[Tensor, Tensor] | None` — `(anchor_positions [B,N],
     keep [B,N])`，给定时跳过 `_sample_anchor_positions`（L566），直接用于
     `_build_block_targets`。调用方保证 anchor 在该物理 group 的 padded S 下有效
     （group 末尾按 `max(anchor)+bs` 补齐，与 harness `pad_to` 一致）。
   - `sample_weights: Tensor | None` — `[B]` fp32；在 `_build_block_targets`
     （L480）返回前乘到 `block_mask` 行上（`mask * w.view(-1,1,1)`）。
2. `vlm_dflash/dflash/decay_loss.py::DFlashDecayLoss`：新增可选
   `weight_dtype: Literal["auto","fp32"] = "auto"`；`"fp32"` 时 `_reduce`
   （L434-442）用 `block_mask.float()` 计算（消除 bf16 权重量化 ~0.4% 的
   loss 值差；shipped 路径显式隔离在 `cp` 对照臂）。
3. 新文件 `vlm_dflash/dflash/regroup.py`（纯 Python，无新依赖）：
   `SampleStat / plan_groups(mode∈{token,dual,cost,grid}, sub_batch, cost_weight) /
   row_weights / iter_physical_groups` — 与 `research/rsi/d1/d1_bucketing.py`
   同源实现（已在 oracle/pipeline 测试与本轮全部 GPU A/B 中使用）。
4. `vlm_dflash/dflash/train.py`：新增可选 config 块
   `train.regroup: {mode: null, sub_batch: null, cost_weight: 147.5, fp32_weights: false}`
   （默认全 null/false ⇒ 现有路径逐字节不变）。启用时：每个逻辑 batch 先冻结
   一张 anchor 表（一次 sampler 调用，CPU/GPU 同 RNG 语义见 §4），按 mode 分组、
   计算 g_i、逐 group 调 forward(anchor_table=…, sample_weights=…) 并用
   `normalize="tokens"` 的 DFlashDecayLoss；backward 后按 shipped 顺序做
   clip/step（更新顺序与 shipped 完全一致）。

## 3. 涉及角色与兼容性

- 消费方：D2（teacher 流按 slot 位置对齐，不受分组影响）、D3（attention 形状
  直方图变化，需重测）；D4 缓存策略不变（regroup 只改物理执行顺序，不触碰
  cache key/命中语义；在线 cache 下重排引入 bf16 teacher 数值漂移，需 D4×D1
  2×2 联合核验）。
- iface：`forward` 新增关键字参数为纯增量，非破坏；PROTOCOL 建议 +0.1（候选，
  由 C0 定）。公共 batch schema / checkpoint 格式不变。
- digest/resume：启用 regroup 时 anchor 采样由每物理批一次改为每逻辑批一次，
  RNG 消耗序列变化 ⇒ 与未启用 run 不可 bit-exact；文档需写明 regroup 启用时
  按**逻辑 batch 边界** resume（现 checkpoint 即为每 optimizer step，天然满足）。
