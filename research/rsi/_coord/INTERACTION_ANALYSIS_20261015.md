# 交互（"打架"）分析：D1–D5 优化组合的风险地图 — 2026-10-15 · C0

- 请求：用户（"A 加速 5%、B 加速 10%，二者同步工作可能 <5 甚至负收益——分析会不会相互打架"）。
- 依据：已归档实测（D4×D1 2×2 等）+ 各成果的收益来源分解；逐项标注「已测 / 未测 / 预测」。本文件是分析，不改变任何判决。

## 0. 结论（TL;DR）

1. **已实测的组合问题只有一处**：D4×D1（2×2）W3 cell 组合数值门 FAIL（1.2475e-2@11 > 门 7.5e-3；bucket_on 两腿）——但 cache 腿字节惰性（floor probe 0.0、交互 bit-0）→ 归因是 **D1 regroup machinery 自身的数值缝**（后由 bug #01 证实），不是 A×B 相互放大。含义：组合会先被"其中一方的短板"拖死（数值门），轮不到速度问题。
2. **速度上最可能"1+1<2"且未测的两对**：**D4×D5**（同吃 producer/regen 供应链 → 替代风险；原计划"D4×D5 producer 重测"未执行）与 **D1×D5**（D1 只缩 train 段 → 进流水线按段权稀释；示意粗算 ≈ −7%，producer 成瓶颈时还可更小）。
3. 其余对（D1×D2、D2×D4、D2×D5）结构上近似加性（不同段/不同资源）；**数值风险几乎全部来自 D1**（D2/D4/D5 在证据上为字节惰性/调度级）。
4. **最"字面"的负收益已经发生过**：共卡竞争（事故 #1/#2/#4/#6：OOM、SIGTERM、contended 作废）——同步工作直接让结果不可用。
5. 通用数学（判断区间的框架）：互不相交的段 → 近似相加；乘性全覆盖 → `a+b−ab`（重叠损失=乘积项，轻）；同一段饱和 → ≈`max(a,b)`；关键路径翻转/数值门/资源冲突 → 可到 ≈0 或负。

## 3. 已发生的负收益形态（实例）

- **共卡竞争**（最直接）：事故 #1（D5×D2 共卡 OOM）、#2（D3×D2 OOM）、#4（D1 被外部 SIGTERM）、#6（check→launch 竞态 OOM）——"同步工作"直接毁掉结果或标 contended。
- **组合数值门**：D4×D1（W3）→ 组合暂禁（`d4xd1-003-c0`）。
- **伪收益陷阱**（别把假测量当收益）：D4 off vs cap10 的 wall 差=编译/冷启动顺序效应（非缓存收益）；D5 sim 预测 −14% vs 实测 −5.3%；D1 round-2 的 +19.0%/+24.7% 系 8 批 cell（不作主数字）。

## 4. 重测清单（组合部署前的前置）

- **P0**：D4×D5 producer 负载重测（原计划缺口）；D1×D5 在 S3 上的端到端 wall（含段权读法）。
- **P1**：D1×D2 同 step 相加性；D2×D4 正交确认（便宜）。
- 方法：A/B/A+B 同协议同卡（quiet）≥3 交替；**先过数值门**（含 D1 的组合当前全部被质量门锁住）；结论只报端到端关键路径，**不乘倍率**；段级 % 不得直接相加。

## 5. 部署建议（当前证据）

- 任何含 D1 的组合：**现在不可用**（质量门先行；bug #01 未结）。
- 组合声明前置：新预注册（含 A/B/A+B 矩阵与数值门）+ C0 独立重算收据；负结果照记。
